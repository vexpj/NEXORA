# Безопасность и секреты

## Правила для репозитория (он может быть открытым)
1. В код, конфиги и тесты **никогда** не добавляются: пароли, токены, ключи API, секреты приложений Azure,
   сертификаты (`.pfx`, `.pem`, `.key`), реальные токены Minecraft/Microsoft.
2. Ключи пользователя (Microsoft Client ID, ключ CurseForge) вводятся в самом лаунчере (Настройки) и хранятся
   **на компьютере пользователя** в `%AppData%\NEXORA`, ключ и токены — в зашифрованном виде (Windows DPAPI).
   В репозиторий они не попадают: этих файлов нет в проекте, а `.gitignore` их блокирует.
3. Microsoft Client ID — публичный идентификатор (не секрет), но его тоже вводят в настройках, а не пишут в код.
4. Сертификат подписи кода (когда появится) хранится только в **GitHub → Settings → Secrets and variables → Actions**.
5. Секреты в CI передаются через `secrets.*` и никогда не печатаются в логи.

## Автоматическая защита
- `build/check_secrets.py` запускается в каждой сборке GitHub Actions и останавливает её, если нашёл похожее на секрет.
- Токен доступа Minecraft маскируется (`***`) в журнале игры.
- Скачивание только по HTTPS с доверенных адресов, проверка контрольных сумм.

## Если секрет всё же попал в репозиторий
1. **Сразу отзовите/перевыпустите** ключ (удаление файла из Git его не спасёт — он остаётся в истории).
2. Удалите его из истории (git filter-repo / BFG) или пересоздайте репозиторий.
3. Сообщите об уязвимости через GitHub → Security → Report a vulnerability.
