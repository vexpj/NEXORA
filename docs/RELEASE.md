# Выпуск обновления и автообновление

## Как выпустить новую версию
1. Поднимите `<Version>` в `Directory.Build.props` (например, `0.3.3`), Commit и Push.
2. На GitHub: **Releases → Draft a new release**, тег `v0.3.3` (должен совпадать с версией), заголовок и описание → **Publish release**.
3. Сборка запустится сама и через несколько минут прикрепит к релизу `NEXORA-Setup.exe`, `NEXORA-Setup.exe.sha256` и `NEXORA.exe`.
   Если тег не совпадает с версией в файле, сборка остановится с понятной ошибкой.

## Как лаунчер обновляется у игроков
- При запуске (можно отключить в «Настройках») и по кнопке в «Новостях» лаунчер спрашивает у GitHub последний релиз.
- Если версия новее, в меню появляется кнопка «⬆ Обновление». Нажатие: загрузка установщика → проверка SHA-256 по файлу из релиза →
  проверка цифровой подписи (если она есть) → установка поверх (Windows спросит права администратора) → перезапуск лаунчера.
- Любая ошибка (нет связи, неверная сумма, недействительная подпись, отказ в правах) оставляет лаунчер прежней версии и показывает причину.
  Если установщик прервётся посреди установки, Inno Setup откатывает изменения.

## Важные условия
- **Репозиторий с релизами должен быть публичным.** У закрытого репозитория GitHub не отдаёт релизы без входа, и проверка обновлений ничего не найдёт.
  Код проверен на секреты (`build/check_secrets.py`), но перед открытием просмотрите историю коммитов. Либо публикуйте релизы в отдельном публичном репозитории
  и поменяйте `UpdateConfig.Repository` в `src/NEXORA.Core/Updates/UpdateModels.cs`.
- Обновление скачивается только с адресов GitHub этого репозитория; список адресов отделён от списка для модов.
- **Подпись кода.** Пока установщик не подписан, целостность обеспечивают HTTPS и SHA-256 из того же релиза: это защищает от повреждённой загрузки,
  но не от взлома вашего аккаунта GitHub. Для публичного релиза получите сертификат подписи кода, храните его только в GitHub Secrets,
  подписывайте установщик в сборке и поставьте `UpdateConfig.RequireSignedInstaller = true`.
